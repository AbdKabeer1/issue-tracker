# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS 4 (CSS-first, no JS config). Auth.js v5 (Google OAuth, optional credentials). Prisma + PostgreSQL. pnpm. Deployed to Coolify in production (ziki.dev); Vercel is used for preview/hosting of this fork.

## Users

Primary: developers, QA, and community members reporting and triaging bugs for Ziku/Ziki/Zedu. They report issues, filter boards, triage status/assignee, vote, comment, and audit decisions.
Secondary: AI agents doing the same work through an agent API (`/api/v1/**`), and site admins/super admins managing catalogs, organizations, users, milestones and rewards.
Third: program managers, instructors and community leads evaluating Zedu (the marketing homepage audience).

## Product Purpose

Ziki Issues is the issue and bug tracker for Ziku/Ziki/Zedu (ziki.dev). Success means issues get reported, triaged, assigned and resolved with a clear audit trail, both humans and agents can pick up work, and the board stays trustworthy at speed.

## Positioning

Team Zendor fork of emerjent/bug-tracker. Its distinguishing mechanism is **agent-first issue tracking**: an agent API with levels, points and reviews sits beside the human workflow, so agents and people triage the same board. Not a generic tracker, and not a generic AI wrapper.

## Operating Context

Served from the root domain at `https://ziki.dev`, with legacy hosts `issues.zedu.chat` and `contributors.zedu.chat/bug-tracker` still resolving. Auth-gated pages expose only safe fields to link-preview bots. Keyboard shortcuts (`n`, `/`, `g i`, `j/k`, `?`) are a first-class workflow and must stay discoverable. Weekly work is organised outside the product in a Google Doc shared by the owner.

## Capabilities and Constraints

- Issue reporting, filtering, bulk triage, comments, votes, attachments, audit log, milestones, points/leaderboard, escalations, questions, workers ranking, team, webhooks, notifications, exports.
- RBAC: site roles `user` / `admin` / `super_admin`, with in-organization membership roles `owner` / `admin`. Site `admin` grants catalog access only; inside an organization, power comes from membership role.
- Agent API at `/api/v1/**` authenticates by agent key, not session; middleware must keep it public and self-authenticating.
- Migrations only — never reseed or reset a database that holds real accounts.
- Print styles, reduced-motion, and skip-link focus management are shipped behaviors, not nice-to-haves.
- Two visual systems coexist today: the token/Tailwind "zk" system (app shell, ~50 screens) and a legacy `components/homepage/homepage.css` system (public landing, DM Sans, its own variable namespace).
- Dark mode is generated by `scripts/generate-dark-palette.mjs` and re-bridged by `app/theme-brand.css`, which is the de-facto brand source of truth.
- Typefaces: Manrope (public), Inter (signed-in shell), DM Sans (homepage), Geist Mono.

## Brand Commitments

Name: Ziki Issues. Logo assets exist at `public/ziki-logo.png`, `public/brand/`, `public/ziki-mark.svg`, plus an inline SVG mark in `components/ziki-mark.tsx`.
Existing brand docs state a calm, quiet, bordered-card language with one primary accent and no gradient headlines or heavy shadows (`docs/brand-guide.md`), while `design-handoff/HANDOFF.md` records the Deep Ocean / Blue Slate / Electric Blue / Sky Tint / Porcelain palette and pill-shaped controls.
**Explicitly superseded for this task:** the owner has requested a complete whimsical re-imagining — "we don't have to stick to old ways of doing things, we can make a completely new design ourselves, not what everyone in the world has seen." The old look is evidence and anti-reference, not authority. Existing logo/name assets and status color semantics (High=bad, Medium=warn, Open=info, Confirmed=ok) are preserved.

## Evidence on Hand

`design-handoff/HANDOFF.md` and 20 light/dark HTML mockups in `design-handoff/designs/`; `docs/brand-guide.md`; `docs/redesign-parallel-plan.md` (multi-agent reskin plan with a Wave-0 frozen-file list); `design-qa.md` (pixel-comparison QA, currently blocked on a populated DB); live site `https://ziki.dev`; repo README and `AGENTS.md`.
Absences future work must not fabricate: no DESIGN.md exists, no `ui/card.tsx` exists, there is no populated test database for pixel QA, and the dark palette file is generated rather than authored.

## Product Principles

- One board for humans and agents, same rules for both.
- Triage speed over configuration; defaults win.
- Every state change is auditable and reversible.
- Legibility and scannability outrank expression on operational screens.
- Accessibility, print and reduced-motion behaviors ship with any visual change.

## Accessibility & Inclusion

Skip link to `#main-content`, visible focus management on route change, `prefers-reduced-motion` honored (`.zk-motion` kill-switch), WCAG AA contrast on every token pair, ≥40px touch targets, full keyboard shortcuts with a discoverable `?` help dialog.
